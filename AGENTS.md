# APEX Discord Snapshot Master

Приложение сохраняет доступную боту историю Discord в локальный SQLite-архив.

## Где работать

- `core/` — Discord API, импорт, схема SQLite версии 2, загрузка и проверка медиа, ресурсы EN/RU.
- `cli/` — запуск, продолжение и проверка архива из терминала.
- `gui/` — WPF на .NET 10, проекты, выбор каналов и запуск локального просмотрщика. Настройки проекта хранятся в `project.json`, токен защищён Windows DPAPI.
- `web-ui/` — просмотрщик на Python 3.10+ и JavaScript без сторонних зависимостей. Читает `snapshot.sqlite` и `media/`. Использует тот же набор Discord Twemoji, что и WPF.
- `installer/` — сборка Windows-установщика через Inno Setup. Команды и требования описаны в `README.md`.

## Проверка изменений

```powershell
dotnet run --project tests
dotnet build gui/DiscordSnapshot.Gui.csproj -p:TargetPlatformDisplayName=Windows
dotnet build cli/DiscordSnapshot.Cli.csproj
node --check web-ui/app.js
python -B tests/viewer_auth.py
docker compose config
```

Тесты импорта используют подменённые HTTP-ответы. Для проверки веб-интерфейса запустите `python web-ui/server.py --archive <путь-к-архиву>` и откройте `http://127.0.0.1:8080`.

## Совместимость и публикация

- Сообщения сохраняются вместе с исходным JSON, включая реакции. Перед изменением SQLite проверяйте совместимость импорта, возобновления и веб-просмотрщика со старыми архивами.
- Корневой `compose.yml` встраивается в `core` и копируется в архив. Он подтягивает тег `latest` и даёт просмотрщику доступ на запись для действий администратора. Для режима чтения используется `DISCORD_ARCHIVE_READ_ONLY=true`.
- Discord OAuth2 включается наличием `.discord-auth.json`. Файл с Client Secret предназначен для владельца архива и процесса просмотрщика. Интеграционные тесты веб-просмотрщика подменяют ответы Discord.
- SSH-проекты используют штатные `scp` и `sftp` Windows OpenSSH. База изменяется локально, новые вложения отправляются сразу, а при синхронизации изменённые файлы проходят проверку конфликта и публикуются через переименование SFTP.
- Контекст Docker-сборки — `web-ui/`. Адрес образа берите из `compose.yml`. Публикуйте собранный образ после проверки его запуска.
- Для разработки используйте тестовые данные. Исключайте реальные архивы, токены и содержимое `project.json` из Docker-образа и репозитория.
